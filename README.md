# Git on Network Drive Investigation Results

## 概要
ネットワークドライブ（H:ドライブ）上で `git status` などのコマンドを実行した際に、応答が極端に遅くなる、またはハングアップする現象について調査を行いました。

## 結論
Git for Windows (MSYS2/MinGW) が行う **パスの正規化処理（`realpath` 等）** が、ネットワークドライブ上では非常に高コストであることがハングアップの主要因です。

## 調査結果詳細

### 1. システムコールのレイテンシ比較
専用のCプログラムを作成し、主要なファイルシステム操作のレイテンシを `H:`（ネットワーク）と `C:`（ローカル）で比較しました。

| 操作 | H: (ネットワーク) | C: (ローカル) | 備考 |
| :--- | :--- | :--- | :--- |
| `getcwd` | **0.007 ms** | 0.006 ms | 現在位置の取得は非常に高速で問題なし。 |
| `GetLongPathNameW` | **约 6.0 ms** | 0.3 ms | Windows APIによるパス変換。遅いが許容範囲。 |
| **`realpath`** | **90.0 ms 〜 120.0 ms** | **0.3 ms** | **致命的なボトルネック（約300倍の遅延）。** |

### 2. ハングアップのメカニズム
Gitは起動直後（コマンドの実処理に入る前）に、設定ファイルの探索やカレントディレクトリの特定のために、パスの正規化（`realpath` 相当の処理）を数回〜数十回行います。
1回の呼び出しに100ms以上かかるため、これらが積み重なることで、ユーザーには「何も表示されずに固まった」ように見えます。
`GIT_TRACE_SETUP=1` を使用してもログが出る前に止まっていたのは、この初期化フェーズで時間がかかっていたためです。

## 回避策 (Workaround)

### **推奨: `--git-dir` を使用する**
カレントディレクトリをローカルドライブ（例: `C:`）に置いたまま、`--git-dir` と `--work-tree` オプションを使ってネットワーク上のリポジトリを操作します。
これにより、Git起動時の「現在のディレクトリのパス解決」という高コストな処理をスキップできます。

```powershell
# 1. ローカルドライブに移動
cd C:\

# 2. オプションを指定して実行
git --git-dir=H:\path\to\repo\.git --work-tree=H:\path\to\repo status
```

### **非推奨: `GIT_CEILING_DIRECTORIES`**
親ディレクトリの探索を制限する `GIT_CEILING_DIRECTORIES` は効果がありませんでした。探索が始まる前の「自身のパス解決」の時点で既に遅延が発生しているためです。

## 調査用プログラムについて
`c_programs/` ディレクトリに、今回の調査で使用した検証用コードが含まれています。
- `test_getcwd.c`: `getcwd` の速度計測
- `test_realpath.c`: `realpath` の速度計測（これが最も遅い）
- `test_getlongpathname.c`: `GetLongPathNameW` の速度計測
- `test_mingw_getcwd.c`: `_wgetcwd` を利用した実装の検証
